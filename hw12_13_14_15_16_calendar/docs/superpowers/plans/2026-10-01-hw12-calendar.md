# Homework 12 Calendar Implementation Plan

**Goal:** Complete the existing calendar skeleton against `../../12_README.md` and `../../CALENDAR.MD`.

**Architecture:** Keep cmd, app, logger, HTTP server and storage packages. The application consumes a shared context-aware storage interface, implemented with a locked map and PostgreSQL database/sql. HTTP serves hello-world only.

**Tech stack:** Go 1.23+, encoding/json, log/slog, net/http, database/sql and github.com/lib/pq.

## Constraints and decisions
- Implement homework 12 only; no business HTTP/gRPC endpoints or queue processes.
- Configuration uses JSON, with optional environment overrides for deployment settings.
- Event intervals are half-open; overlap is prohibited only for the same user. Adjacent events are allowed.
- Listings select event start times in [from, to), sorted by start and ID. Day/week/month boundaries use the supplied date's location; month starts on the first.
- IDs are supplied by callers. Validate nonempty ID/title/user, start time, positive duration, nonnegative optional reminder.
- Log requests to stdout by default, and optionally to a configured file as well.
- SQL migrations are applied manually; PostgreSQL btree_gist exclusion constraint makes overlaps atomic under concurrency.
- Work in the user-authorized current homework directory; no VCS mutations.

## Review focus
- Mutating events or returned reminder pointers must not mutate stored values.
- Update conflicts must preserve old data; missing IDs must return ErrNotFound.
- Concurrent overlap inserts must allow exactly one winner.
- HTTP logging must preserve the first response status and include implicit 200.
- Invalid configuration must fail before resources are started; SQL errors must not expose credentials.
